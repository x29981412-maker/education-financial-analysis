# 项目收款多场景核对与月末差异分析

围绕分期收费项目的业务台账与银行流水，研究单笔收款、合并与拆分、月末跨期及同额歧义四类情况。比较不同核对规则下的自动覆盖、误配和待查数量，并保留从汇总结果返回原始记录的路径。

**[查看完整报告](paper/main.pdf)** · [报告文字版](paper/report.md) · [结果摘要](results/summary.csv) · [核对方法](docs/method.md)

## 四类核对场景

| 场景 | 要解决的问题 | 方法 |
| --- | --- | --- |
| 单笔收款与退款 | 相同金额是否属于同一笔业务 | 编号、币种、方向、日期与身份冲突检查 |
| 合并与拆分入账 | 一笔银行记录如何对应多条台账，或反向对应 | 同业务范围内的有界组合搜索 |
| 月末与期后到账 | 截止日差异是否有后续记录支持 | 期间范围控制、期后证据单列与差异分解 |
| 同日同额与信息缺失 | 资料不足时是否应自动确认 | 双向唯一候选、保留歧义与待查清单 |

## 方法设计

所有金额在读取时转换为整数分。先检查输入质量，再按编号、组金额、项目与付款方逐层建立对应关系。每条记录最多使用一次；共享记录的候选组合不会按文件先后顺序强行确认。

```mermaid
flowchart LR
    A[业务台账与银行流水] --> B[字段与输入质量检查]
    B --> C[编号唯一核对]
    C --> D[合并拆分与身份补充]
    D --> E[期后证据与差异分解]
    E --> F[匹配明细 原始行追溯 待查清单]
```

## 实验结果

固定种子47生成241行台账、227行银行流水，其中5行银行输入因重复编号或字段问题隔离。标签仅用于评价，不输入核对程序。

| 策略 | 自动匹配组数 | 误配组数 | 组级精确率 | 台账覆盖率 | 待核对台账 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 编号唯一核对 | 144 | 0 | 100.00% | 59.75% | 97 |
| 编号与身份分层核对 | 184 | 0 | 100.00% | 86.31% | 33 |
| 金额日期优先 | 204 | 8 | 96.08% | 94.61% | 13 |

分层核对比仅按编号多确认40组，将待核对台账由97条降至33条。同日同额样例中，金额日期优先提高了覆盖率，也产生8组误配。扩大自动确认范围需要额外业务证据。

以上均为可复现的模拟结果。同日同额样例用于检验信息不足的情况，场景占比不代表真实企业。期后到账仍不计入截止日银行发生额；分解校验为零也不表示所有交易已经核清。

## 从业务问题看核对

- **业务范围：** 相同金额只是候选条件，项目、付款方和业务编号共同决定是否存在可靠对应。
- **期间口径：** 后续到账能够解释时间差，需要同时保留截止日余额和期后证据。
- **复核取舍：** 自动覆盖和误配需要一起比较，保留待查记录也是核对流程的一部分。

```text
src/receipts/                输入、核对、实验与命令行实现

```

Python 3.11或以上，核心计算不依赖第三方库。在仓库根目录运行：

```bash
python scripts/run_experiment.py
python -m unittest discover -s tests -v
```

测试包括五个额外随机种子下的约束检查。重新生成数据和CSV结果后，可以与仓库中的文件逐项比较。

需要重新生成PDF时，额外安装报告依赖：

```bash
python -m pip install -e ".[report]"
python scripts/build_report.py
```

使用自己的CSV文件及字段要求见[数据说明](docs/data.md)。结果CSV可以用Excel打开。运行自有数据时不会读取模拟标签，当前版本也不会自动写入会计调整或替代人工确认。

方法参考与依赖说明见[参考资料](docs/references.md)。样例不来自任何真实公司，不包含实际留学项目、学生或银行账户信息。
