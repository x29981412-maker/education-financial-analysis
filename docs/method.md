# 核对方法

## 输入与范围

台账范围为期间起点至截止日，银行流水范围为期间起点至截止日后N日。当前版本没有导入期初未达项。范围外的有效行仍保留在追溯表中，隔离行另列。

金额使用十进制解析后转为整数分。正数表示收款，负数表示退款或支出。超过分的精度报错，不做隐式舍入。币种字段按三个英文字母检查，不做汇兑。

同一来源的记录编号重复时，全部重复行隔离。输入文件的SHA-256用于检查原始文件是否改变。字段统一仅处理全半角、大小写与空白，不对付款方名称做模糊归并。

## 候选关系

设台账集合为L，银行记录集合为B。单笔候选满足币种相同、金额方向相同、日期差不超过窗口。自动确认的对应关系还要求金额精确相等。

1. **编号层：** 非空业务编号相同；若项目或付款方在两侧均有值而互相冲突，则不确认。候选两侧均唯一才确认。
2. **组合层：** 业务编号、项目、付款方、币种共同限定业务桶。在桶内搜索一对多或多对一关系，最多组合四条。每个成员分别满足日期窗口和方向条件，组金额相等。超过十二条的桶不做组合搜索。
3. **身份层：** 对剩余记录，要求非空项目和付款方相同、金额相等。两侧均有但互相冲突的业务编号不降级匹配。候选仍须双向唯一。

设候选组g是否确认由二元变量x(g)表示。对每一条原始记录i，要求：

$$\sum_{g:i\in g}x(g)\leq 1.$$

已确认组满足：

$$\sum_{i\in L_g}a_i=\sum_{j\in B_g}a_j.$$

组合存在共享成员时，相关候选都保留待查。这种规则优先控制冲突，可能错过需要更多人工资料才能辨别的真实组合。组合层不求解一般多对多的全局最优分配。

## 比较策略

“编号唯一核对”仅使用编号层。“编号与身份分层核对”使用上述三层。“金额日期优先”先使用编号和组合层，再将剩余同币种、同方向、同金额的记录按日期距离、记录编号排序选择。第三种策略用于展示覆盖率与证据充分程度的取舍，不作为默认策略。

## 截止日差异分解

所有统计按币种分别计算。记L为当期有效台账发生额，B为截止日有效银行发生额，T为已匹配组的台账金额与该组当期银行金额之差，U(L)和U(B)分别为未匹配台账和当期银行金额，则：

$$L-B=T+U(L)-U(B).$$

期后银行记录在匹配过程中作为证据使用，在B中不计入。T可能包含合并组内部分到账在期后的情况，不一律等于整组金额。校验剩余数检查程序是否遗漏或重复计入记录，不用于证明账面余额正确。

## 评价与解释范围

组的成员及对应关系与独立标签完全一致才算正确。组级精确率为正确自动组数除以自动组数，组召回率为正确组数除以标签组数。台账覆盖率按被自动确认的台账条数计算，不按金额加权。

同日同额样例中，隐藏标签的对应关系无法由输入字段唯一识别。因此这部分数据用于检验歧义处理。标签不读取、匹配结果可追溯和分解守恒共同构成实验验证，但不能证明对未知业务数据普遍有效。
